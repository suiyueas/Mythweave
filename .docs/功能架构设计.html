十五、多Agent协同工作室

Multi-Agent Studio
  • · 编辑Agent：节奏分析 + 逻辑矛盾检测 + 伏笔回收率评估
  • · 人物Agent：守护人物行为一致性 + 对话风格匹配

API 通讯架构

前端 (Vue3) ├── HTTP REST → 常规CRUD + Agent调用 + 巡查触发 + 全局搜索 + 文件上传 ├── SSE (EventSource) → AI流式续写/对话/章节生成/标题生成（含上下文装配注入） └── WebSocket → 实时状态同步 + 主动推送告警/巡查结果/Agent分析通知 后端 (Spring Boot) ├── Controller层 → 14个REST Controller（含Ai/Chapter/Character/Plot/Outline/Search/Sentinel/Style等） + SSE端点 ├── Service层 → 10个业务Service + Agent编排(Orchestrator) ├── Agent层 → Orchestrator自研编排器（编辑/人物/风格/读者 4 Agent并行调度） ├── Context层 → EmbeddingService / ContextAssembler（双源融合：MySQL结构化+ES语义检索） / ESSearchService / NovelContextIndexService ├── Sentinel层 → SentinelService（定时巡查 + 事件驱动 + 四维巡检） ├── Style层 → StyleEngineService（五维特征提取 + 相似度评分 + 进化追踪） ├── AI Client层 → DeepSeekClient（流式/非流式双模式）+ PromptTemplates + QianwenEmbeddingClient └── Repository层 → 26个MyBatis Plus Mapper + ElasticsearchClient

关键技术决策

1

流式输出

Spring SSE（Server-Sent Events），前端EventSource接收，编辑器实时渲染

2

版本管理

章节采用增量存储+版本链，支持diff对比

3

富文本编辑器

前端自研Vue组件编辑器，支持Markdown + 富文本双模式，内嵌AI流式续写交互

4

AI调用封装

DeepSeekClient统一管理Prompt、重试、Token计数、流式/非流式切换

5

缓存策略

Redis缓存热点数据（大纲树、人物列表），减少DB查询

6

RAG上下文引擎

千问text-embedding-v3做中文向量化（1024维），ES 8.x存储向量索引，dense_vector + kNN + BM25混合检索，写作时自动装配全书相关上下文注入AI调用

7

多Agent协作

自研Orchestrator编排4个专精Agent（编辑/人物/风格/读者），支持同步单Agent、异步批处理并行（CompletableFuture线程池）、对话三种模式。

⚠ 复杂度说明：多Agent并行时存在上下文传递开销（Token消耗约为单Agent的3-4倍）、结果冲突消解（Orchestrator加权仲裁）。
降级方案：Token预算紧张或响应延迟超标时，自动降级为"串行优先模式"——优先运行编辑Agent，仅当检测到明确问题域时才唤起对应专精Agent。
8

主动智能哨兵

Spring @Scheduled + Redis异步任务队列，章节完成事件驱动 + 每日凌晨全书深度巡查，伏笔/逻辑/人物/节奏四维巡检

9

风格引擎

五维风格特征提取（句式/词汇/修辞/叙事/标点），结构化风格配置文件，AI续写时注入System Prompt约束文风匹配

10

ES混合检索

语义向量相似度 + BM25关键词匹配加权融合，兼顾"意思相近"和"关键词精确命中"

11

存储分层

MySQL主库管业务CRUD + ES管向量检索/全文搜索/日志聚合 + Redis管缓存/队列，各司其职无需替换数据库
